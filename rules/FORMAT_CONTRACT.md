# Markdown 與 HTML 格式契約

本文件是 Script 輸入、HTML 輸出與格式 lint 的唯一規格。

## Markdown frontmatter

每份 `corrected.md` 必須包含：

```yaml
---
id: EP62
document_role: student_worksheet
audience: 台灣大專生與初入職場者
source_document: https://docs.google.com/document/d/...
category: 避開職場常見問題與陷阱
hero_kicker: 這點薪水憑什麼要我拚？
hero_title: 努力，有回報嗎？
hero_accent: 有回報嗎？
hero_question: 工作薪水和付出不成比例，該繼續努力、溝通，還是換工作？
---
```

- `id`：檔案識別碼，英文字母使用大寫。
- `document_role`：學生版固定為 `student_worksheet`。
- `audience`：實際目標客群，不得留白。
- `source_document`：原生 Google Docs 連結或可定位來源的字串。
- `category`：顯示在每頁頁首的網站分類名稱，只能使用下列六種固定值之一：
  - `學會和別人相處、不互相傷害`
  - `處理情緒低落、焦慮和壓力`
  - `看懂社會為什麼這樣運作`
  - `避開職場常見問題與陷阱`
  - `找到自己的特質與使用方式`
  - `改善生活習慣、提升效率`

  不得填入單篇主題、學習目標或另創系列名稱。已列入 `site/worksheets.json` 的學習單，`category` 必須與該 EP 的網站分類完全一致。
- `hero_kicker`：主視覺上方的小標。
- `hero_title`：主視覺的大標題。
- `hero_accent`：`hero_title` 中使用深綠色強調的完整文字，必須是大標題的一部分。
- `hero_question`：大標題下方的一句核心提問。

只使用這一組欄位與共用版型。未定義的 frontmatter 欄位，以及舊欄位 `series_title`、`font_profile` 與舊註解 `section-note`，lint 都會直接拒絕，避免規格外資料被忽略、頁首誤用自訂文字或退回不同樣式。

## 公開網站 Index 的分類顯示

`category` 在公開網站首頁只供主題篩選與搜尋使用。每筆 Index 結果不得顯示分類名稱或分類標籤；所有 EP 一律適用，不設單篇或特定分類例外。學習單內頁仍依本契約在每頁頁首顯示固定分類名稱。

## 公開網站 Index 的搜尋資料

`site/worksheets.json` 是每篇公開內容搜尋資料的唯一來源。每筆資料必須使用 `searchTerms`，不得保留舊欄位 `keywords`。`searchTerms` 只能包含以下五個字串陣列：

- `situations`：使用者正在經歷的具體情境或困難。
- `feelings`：使用者描述自己的感受、壓力或內在狀態時可能使用的詞句。
- `decisions`：使用者考慮採取的行動、選擇或下一步。
- `phrases`：使用者可能直接輸入的自然口語句子。
- `concepts`：影片使用的正式概念、理論或主題名稱。

每篇至少提供兩個 `situations`、兩個 `feelings` 與兩個 `decisions`。所有詞去除頭尾空白後不得為空、不得少於兩個字元，同一篇內不得重複。搜尋詞應以使用者描述問題時會使用的語言為主，不以分類名稱、過度寬泛的單字或影片文案關鍵字湊數。

全站共用的同義詞、停用詞與搜尋權重只定義於 `site/search-config.json`。同義詞只表示跨內容通用的語意近似，例如「辭職／離職」；「某個問題應對應哪一篇內容」必須由該篇的 `searchTerms` 表達，不得寫入全站同義詞。

停用詞不得單獨產生搜尋結果。完整命中失敗時，相關結果必須同時通過 `site/search-config.json` 定義的最少命中詞數、查詢覆蓋率與最低分數，不得因任一單字命中就顯示；只有停用詞的查詢視為沒有符合結果。實際門檻以設定檔為唯一來源，不在其他文件複製數值。

`tests/fixtures/site_search_cases.json` 保存使用者查詢與預期第一名 EP。每個公開 EP 至少包含兩個案例，其中應涵蓋簡短查詢及自然語句。排名案例必須透過 `site/assets/search-core.js` 的正式搜尋演算法執行；只檢查 JSON 是否包含查詢文字不算通過。新增或修改 `searchTerms`、全站搜尋設定或搜尋演算法時，相關排名案例必須同步更新並全部通過。

## 最小可建置範例

複製下列結構，替換文字後即可執行 lint 與 build：

```markdown
---
id: EP63
document_role: student_worksheet
audience: 台灣大專生與初入職場者
source_document: https://docs.google.com/document/d/...
category: 避開職場常見問題與陷阱
hero_kicker: 影片主題小標
hero_title: 一句大標題
hero_accent: 大標題
hero_question: 一句核心提問？
---

# Ep.63 完整影片標題

**使用說明：** 一段簡短說明。

## 01 第一個區塊

### 第一題（單選）

- [ ] 選項一
- [ ] 選項二

<!-- page-break -->

## 02 第二個區塊

### 第二題（可複選）

- [ ] 選項一
- [ ] 選項二

<!-- final-reminder -->
> 符合本篇主題的提醒句。

<!-- with-arrow -->
> AI 幫幫忙：符合本篇任務的操作說明。
```

`hero_accent` 必須逐字出現在 `hero_title` 中；題型、分頁與填答欄位依下節標記。

## 文件結構

- 只有一個 H1，作為學習單主標題。
- H1 保存完整影片標題；頁尾會自動移除開頭的集數並顯示其餘文字。
- 主要區塊使用 H2，格式為 `## 01 區塊名稱`，從 `01` 連續編號。
- 題目或作答指令使用 H3。
- 不帶單選或可複選標記的 H3 視為題目內的小標題，以淺灰底色與左側深綠色線條區隔；真正的作答題目不套用此底色，選項則維持淺綠底色。
- 第二頁前使用獨立一行 `<!-- page-break -->`。
- 一份學習單最多兩頁，因此最多一個 page-break。
- 不使用空格、全形空白或大量底線控制視覺位置。

## 題型標記

### 單選

```markdown
### 我目前比較想怎麼做？（單選）

- [ ] 先繼續觀察
- [ ] 和相關的人溝通
```

### 複選

```markdown
### 哪些項目需要改善？（可複選）

- [ ] 薪水
- [ ] 工作內容
- [ ] 其他（請填寫）
```

### 單選矩陣

```markdown
<!-- matrix-single: 滿意 | 普通 | 不滿意 -->
- 目前的薪水
- 目前的工作內容
<!-- end-matrix -->
```

矩陣標記內只放非空白的 `- 列題目` 與空白行，不得使用 `- [ ]` 選項清單；說明、標題、分頁及其他填答標記放在矩陣外。lint 遇到矩陣內無法呈現的內容須回報行號並停止建置，不得默默略過。調整位置時保留原文與題意；位置不明時先確認。

### 短答與長答

```markdown
<!-- short-answer: 目前最需要改善的一項是 -->
<!-- long-answer: 我想補充的是 -->
```

- `其他（請填寫）` 由 Script 自動附加短文字欄。
- 不在選項後加入底線。
- 填答欄本身會顯示提示文字；若前一個粗體標籤只重複「請寫下情境／觀察」等相同內容，刪除粗體標籤，只保留填答欄提示。lint 會拒絕此類重複標示。
- 日期若不需要瀏覽器日期控制項，使用短答並在標籤中寫明格式。
- 時間格式依 [內容校正規則](CONTENT_CORRECTION_RULES.md#依任務補充時間資訊) 決定，直接寫入既有 short-answer 標籤。Script 原樣呈現標籤，不依「完成時間」等關鍵字替換句型。例如 `<!-- short-answer: 預計完成日期（年／月／日） -->`。

### 自動計分

需要將單選題中標示為全形括號分數（例如 `（3 分）`）的已選選項加總時，使用：

```markdown
<!-- score-total: 總得分 -->
```

此欄位由瀏覽器自動更新，不能手動輸入。只計算同一份學習單中帶有分數標示的單選選項；未選擇任何計分選項時保持空白。

## 支援的 Markdown

Script 支援 frontmatter、H1～H3、一般段落、粗體、無序清單、選項清單、引用文字、page-break 與本文件定義的題型註解。未知題型註解與 H4 以上標題會停止建置；其他 Markdown 語法在使用前必須先擴充 parser、lint 與測試。

### 提示框

提醒句、操作提示或 AI 輔助說明統一使用單行引用文字：

```markdown
> 提示內容。

> AI 幫幫忙：操作說明。
```

提醒句直接寫內容，不顯示「小提醒：」字樣。AI 幫忙提示一律使用「AI 幫幫忙：」作為名稱，並與說明放在同一行；不要另用 H2 或 H3 製作提示框標題。每份學習單結尾都必須依序包含最後提醒句與 AI 幫忙提示；原稿缺少時，依該篇主題與既有任務增補，不另逐篇確認。

提示框預設不顯示箭頭，並使用細分隔線。只有 AI 幫忙提示可顯示綠色箭頭；在引用文字前加入獨立一行 `<!-- with-arrow -->`。其他提醒、分數解讀與鼓勵文字不得使用綠色箭頭。

```markdown
<!-- with-arrow -->
> AI 幫幫忙：操作說明。
```

在最後提醒句前加入 `<!-- final-reminder -->`。只有這個最後提醒的上方使用粗分隔線，且不顯示箭頭；其他提示框維持細分隔線。

```markdown
<!-- final-reminder -->
> 提醒內容。
```

需要提供較長、可整段複製的提示語時，使用提示語引用框。引用框保留內容的段落與無序清單，版面只使用左側深綠色長直線，不顯示箭頭或上下分隔線：

```markdown
<!-- prompt-quote -->

第一段提示語。

- 必要條件一
- 必要條件二

<!-- end-prompt-quote -->
```

相鄰區塊若各自帶有水平分隔線，輸出只保留一條；最後提醒的粗上框線除外。

每個提示語引用框由 Script 自動加入「複製提示詞」按鈕。按鈕只複製引用框內的提示語正文，不包含按鈕文字；成功後短暫顯示「已複製」，列印時隱藏。若瀏覽器無法使用 Clipboard API，改用本機複製備援，不傳送內容。

`prompt-quote` 起訖標記必須成對且不可巢狀，框內至少包含一段正文或一個無序清單項目。框內只支援一般段落、無序清單與 `example` 標記；標題、題型及分頁標記放在框外。lint 遇到未閉合、孤立、空白、巢狀或不支援的內容時停止建置。

舉例類內容一律使用單行舉例標記，放在它所說明的填寫區或選項正下方，獨立換行並以灰字呈現。不得另設「範例」或「例如」標題，再把多個範例集中於獨立區塊。舉例也可放在一般段落或提示語引用框內：

```markdown
- [ ] 因為小事花大錢
<!-- example: 早上錯過公車，晚上就去吃饗食天堂 -->
```

輸出會顯示為「例如：早上錯過公車，晚上就去吃饗食天堂」的灰色獨立一行。

Markdown 表格（表頭後接以 `|` 分隔的連字號對齊列）目前不支援；lint 回報表頭行號並停止建置。不得自動刪除表格或改為其他題型；保留原文，確認呈現方式後再處理。一般文字中的 `|` 與 `matrix-single` 選項分隔符不視為表格。

## HTML 映射

| Markdown | HTML |
|---|---|
| `（單選）` + `- [ ]` | 同名 `radio` 群組 |
| `（可複選）` + `- [ ]` | `checkbox` 群組 |
| `matrix-single` | 每列一組 `radio` |
| `short-answer` | 單行文字欄 |
| `long-answer` | `textarea` |
| `其他（請填寫）` | 選項加單行文字欄 |
| `page-break` | 新的 A4 `.page` 容器 |

## HTML 輸出要求

- 一律套用 `templates/worksheet.html` 與 `templates/worksheet.css` 的核准樣式，不提供簡化版或樣式切換欄位。
- 頁首顯示 EP 編號、固定網站分類名稱與頁數；頁尾顯示 EP 編號及影片標題，不顯示頁碼。
- 主標題保留核准字體與深綠色強調，區塊編號使用深綠色。
- 每道單選、複選與矩陣題都在題目右側顯示灰色作答模式。
- 選項使用淺綠色塊，不以底線取代色塊；A4 列印亦同。
- 同一題只要有任一選項去除空白後超過 12 個字元，該題所有選項一律各自占一行；其他題組維持核准的多欄排列。
- 使用說明使用淺灰字，不加上下橫線。
- `lang="zh-Hant"` 且包含 viewport。
- A4 直式列印；每個 `.page` 固定為一張 A4，工具列在列印時隱藏。
- 支援至少 320 px 寬度，不產生水平捲動。
- 不只靠顏色傳達必要資訊，黑白列印仍可辨識層級。
- 所有輸入控制項都有可見標籤或 `aria-label`。
- checkbox、radio、input 與 textarea 使用 `sessionStorage` 暫存。
- 提供「清除本次暫存」；不發出答案上傳請求。
- 提示語引用框提供一鍵複製按鈕。
- 輸出不得依賴外部 HTTP／HTTPS 資產。
- HTML 不得留下 `{{...}}` 模板標記。

## Lint 狀態

- `fail`：Script 無法可靠建置，必須先修正。
- `warning`：可以建置，但需要人工或模型確認。
- `pass`：所有機械規則通過；不代表視覺 QA 已完成。

## HTML 驗證狀態

- `machine_checks`：只依 Script 的機械檢查判定 `pass` 或 `fail`，不受視覺 QA 結果影響。
- `visual_qa`：記錄風險分級 QA 結果 `pending`、`passed` 或 `failed`；`passed` 可表示本輪完成適用的瀏覽器檢查，或確認變更不影響畫面並沿用既有視覺 QA 基準，適用條件與檢查範圍依 [工作流](../workflow/WORKFLOW.md#5-validate)。A4 列印以固定版型及 Script 檢查為準，預設通過，不另要求人工列印 QA。
- 整體 `status`：機械檢查或視覺 QA 任一失敗為 `fail`；機械通過但視覺待驗為 `warning`；兩者皆通過才為 `pass`。
- `errors` 與 `warnings` 保留各項原因；視覺結果以 `visual-qa-failed` 或 `visual-qa-pending` 識別。

### 報告版本辨識

`validate` 自動記錄 `fingerprints.html`，包含 HTML 的 `path` 與原始位元組 SHA-256 `sha256`；專案內路徑相對於專案根目錄。`check-report` 只讀取報告並比對檔案，回報 `current`（一致）、`stale`（變更或無法讀取）、`unverified`（缺少必要指紋）。只有 `current` 的結束碼為 0，其餘版本狀態為 1；報告無法解析為 2。

版本一致不代表驗收通過，仍須檢查報告原有結果。HTML 指紋不涵蓋外連的本機字型等資產；資產改動後仍須重新 validate，並依工作流觸發完整視覺 QA。模板或 corrected 更新後，先重新 build，再驗證；不能僅憑舊 HTML 指紋一致判定產物已更新。
