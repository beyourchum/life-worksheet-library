# 品質檢查與修正方式

本文件是本站內容與技術驗收的唯一規則來源。全站數值門檻只放在 [quality-policy.json](../config/quality-policy.json)；特定頁面經核准的字型或影片例外只放在 [quality-exceptions.json](../config/quality-exceptions.json)。不得在文件或程式另存一份可變設定，也不得把單篇例外套用全站。

## 共通內容品質

每題須有清楚目的、作答規則、預期產出與前後依賴，並以代表答案逐題試填。依學習目標選擇經驗辨識、概念運用、比較或行動整理，不強迫每份學習單包含所有階段。短答與敘述空間須符合預期答案；選項、比較維度與作答分支須完整；範例不能取代必要資訊或讀者答案。個人經驗與偏好可有不同答案；知識、配對、計算及依據判斷題須提供判準。

內容設計、審查與補充由 `worksheet-content-tw` 負責；`worksheet-web-publish-tw` 負責忠實轉換、互動與技術驗收，發現稿件問題時交回內容技能修正。本站固定區塊、元件、影片與發布規則不自動套用其他網站。有效來源依 [內容來源與同步](workflow.md#內容來源與同步) 判定。

## 內容結構與作答設計

以下規則適用於本站新增內容、文字修改、題型轉換與版型調整，且同時約束修訂稿與 HTML。內容端須先完成成稿，再做代表答案試填、人工驗收及自動檢查；不得先交付缺漏稿，等檢查器補出題目、指令、判準、選項、限制、範例、作答位置、前後依賴、結尾或 AI 提示詞。

首次製作須完成逐題來源對照與人工驗收。既有頁面只重驗受影響內容及前後依賴；未受影響且仍具體可信的證據可沿用，但須說明範圍。流程文件修改只檢查文件一致性與連結，不觸發網站產生或瀏覽器測試。

### 原稿忠實度與修改範圍

- 「轉換」或「製作 HTML」預設只改格式。以交付的學習單及授權內修正為內容依據；文章、簡報與影片只供追溯，不能冒充既有題目。既有修訂稿或 HTML 不因較新、已發布或測試通過就自動成為內容權威。
- 保留原題、選項、上限、作答條件、比較對象與維度、計算方式、活動順序及前後依賴。可以拆欄或改版面，但不得縮減原題要求的產出、合併成無法逐項作答的長欄位，或只依影片主題重新設計。
- 補齊目標、說明、範例、結尾及 AI 區時，只能服務原活動。原稿若要求先使用 AI 再作答，保留該依賴，不能移到頁尾 AI 區取代。
- 依使用者指定問題與已核准方向修改。若選項、尺度、來源或教學目的互相矛盾，列出原文、影響與建議，只把需要判斷的部分標為待確認；明確漏字、結構錯誤與已授權修正直接處理。
- 首次製作在既有修訂稿用本機 HTML 註解記錄「來源 → 修訂稿 → HTML 題組／欄位 ID → 保留或修改依據 → 待辦」；後續只更新受影響部分。選項須逐項核對。註記不公開、不另建重複驗收檔，也不能代替驗收。
- 驗收須雙向進行：由原稿查遺漏與變意，再由 HTML 反查新增或改寫的依據。MD 與 HTML 文字相同只代表同步，不代表忠實。
- 文字替換須限定檔案、完整詞句及位置，並檢查每個命中的上下文。不得以全篇或整批替換單一中文字處理缺字。

### 每篇必備內容與小標題

1. 主標以讀者看得懂的問題或動作，直接說明這份學習單要協助完成什麼；不得沿用需要先知道人物、作品、節目梗或影片脈絡才看得懂的來源標題。索引 `title`、HTML 唯一 `h1` 與修訂稿一級標題一致，瀏覽器標題為「EP編號｜主標」。來源文章或影片全名保留在來源資料與頁尾，不取代學習單主標。人工驗收時遮住集數與來源資訊，只讀主標仍須能說出練習的核心任務。
2. 主標下方只有一則 `hero-question`，以問句指出學習單能協助解決的具體問題；不得只寫主題、宣傳語或承諾未涵蓋的結果。
3. 頁首依序只有「學習目標」與「使用說明」，隨後進入第一個活動。對象、年級、預備知識、時間或必要條件整合進使用說明，不新增第三欄。目標說明完成後能做什麼；使用說明交代活動路徑、個人或討論方式，以及適用的答案判準。
4. 最後一項練習後放唯一的主題結尾，再放「AI 幫幫忙」與可直接複製的提示詞。HTML 結尾使用 `final-reminder`；AI 區使用 `prompt-intro`、`prompt-quote`、`data-prompt-text` 與 `data-prompt-copy`。
5. `prompt-intro` 固定包含綠色箭頭 `closing-mark` 及一段引導文字。引導依序說明 AI 能協助的具體產出、前文作答會自動代入或需要自行填寫，以及該主題必要的隱私或判斷提醒；不得只顯示「AI 幫幫忙」標題。各頁可依風險省略不適用的提醒，不堆疊與任務無關的制式警語。
6. `prompt-quote` 內固定使用 `prompt-copy-text` 承載 `data-prompt-text`，其後放置 `data-prompt-copy` 按鈕。提示詞不用成對引號包住全文，預設依「情境與目標 → 前文作答 → 具體任務與輸出 → 必要界線」排列；只有輸出確實需要多個固定項目時才使用條列。
7. 提示詞每個括號須使用能辨識來源的名稱，並在 `assets/worksheet.js` 的 `promptBindings` 依順序對應前文欄位。可取得的答案自動代入，未作答保留括號；不得同時要求讀者再次手動貼入同一份作答。確實沒有前文來源時才用 `manual` 記錄理由，並在引導及括號中明示「請自行填寫」。組合多欄時，內容稿先寫明範圍與順序。
8. 提示詞使用直接、具體的繁體中文。角色設定只有在能限制回覆方法時才保留；不得用角色名稱取代任務、輸出格式或判斷界線。結尾明示 AI 不得編造資料、越過讀者界線或代替讀者做最後決定；醫療、法律、財務、安全或個人資料等提醒依題目風險具體撰寫。
9. `final-reminder` 位於所有作答欄位之後、AI 區之前。活動中只留完成當題所需的提示；搬移總結時同步 MD／HTML，不留重複段落，也不刪除作答條件。
10. 分組、情境及示範等活動小標題使用灰綠底的 `h3.subheading`。小標題文字不得以數字、英文字母或其標點作流水號，例如「1.」「2、」「A.」「B、」；直接以可辨識的標題文字呈現。情境標題只作辨識，完整敘述與指令放在內文；題目、說明及作答標籤置於對應標題下。

排版須讓讀者知道要做什麼、依據什麼、在哪裡回答。修改題型時先核對原問題、提示與作答區，移除被替代的舊作答區，但保留目的不同的分步練習。必要提示與判準不得因版面調整而消失。

比較可用表格，選擇判斷可用選項；元件由題意決定，不是固定模板。生活說法與可用語彙的一對一對照使用無表格線的 `term-pairs`／`term-pair`，每張卡片一組，手機改單欄。

開放題優先依思考順序拆成可獨立回答的欄位；時間、地點、人物、當下行動、感受、原因、意義與下一步等不同向度各自填寫，不得只用頓號、斜線或括號列在同一標籤後，再交給一個長答框統包。固定句型若包含三個可獨立判斷的內容，也拆成三個有意義的欄位，不把整句做成一個長答框或欄內占位文字。只有拆分會改變題意，或答案必須整體呈現才能判讀時，才保留長欄。每個開放欄位下方都提供貼合該欄、以「例如：」開頭的灰色小字示範；不得用其他前綴，也不得只在同組第一欄提供一次。示範須另起一行，放在填答欄的橫線下方，不得放進填答控制或綠色選項格內。

自動檢查負責攔截結構、順序、提示詞設定、標題一致性、額外頁首欄位、結尾提前或重複；人工驗收負責判斷語意、學習目標、MD／HTML 對應及視覺層級。關鍵字存在不代表通過。

### 填空與多行填答的判斷

- 先寫出足以完成原題的代表答案，再依答案形式與長度選控制；題目長、屬開放題或原稿有大框都不等於需要 `textarea`。
- 時間、日期、數量、人物、名稱、類型、主題及單項能力，若能以數字、短詞或短句完成，使用 `input.short-answer`；「其他」使用 `other-input`。保留單位，欄寬符合答案長度。
- 只有需要說明原因、描述經過、分析觀點或交代做法時才使用多行欄位，並提供合理空間。
- 同題同時含短資訊與敘述時分開設欄，不用一個大框統包多個底線，也不要求重複填寫。拆欄後逐欄使用符合代表答案長度的控制：短詞或短句用單行欄，需要解釋才用多行欄。原有選擇題仍依其功能保留。
- 有明確公式且可由輸入推算時，分開輸入與唯讀結果，保留公式、單位與取整規則；空白或無效時不顯示結果。測試輸入修改、選項切換、暫存還原、清除與列印。
- 改控制時同步修訂稿與 HTML；欄位意義未變則保留 ID。人工驗收逐欄核對答案、控制類型及網頁／列印空間。

### 題型與表格的判斷及驗收

新增或修改題型、欄位與表格時，先確認原題產出和前後依賴，再選元件；內容穩定後才調分頁。題型驗收是獨立結果，不能併入「版面正常」或「技術測試通過」。

#### 製作前的逐題判斷

在既有修訂稿註記「作答動作 → 代表答案 → 欄位／表格形式與理由 → 下一步如何使用」。代表答案只供驗收，不預填給讀者。

- 辨識選擇、排序、計算、比較或敘述；同題有多個動作時保留各步產出。
- 單選、複選、上限與排序不可只改標示文字。逐項保留選項、上限範圍、排序對象與方向、名次範圍及同名次規則；矛盾時提出原文待確認。
- 特殊題型須在內容稿定義初始狀態、讀者動作、有效與無效狀態、確認或重做、結果用途及紙本替代作法，不能只藏在 HTML／JavaScript。
- 比較題列出所有對象、維度與每格產出。多對象不能縮成長答框；分類細項不能只剩分類名稱；勾選、評分與理由不能互相取代。
- 一對一語彙對照使用 `term-pairs`；交叉比較使用表格或矩陣。手機轉卡片時仍須保留每格的對象、維度與控制對應。
- 表格標題及列、欄標頭須能辨識每格用途；原生表格使用適當 `th`、`scope` 或標頭關聯。控制須有可辨識名稱，欄寬與書寫空間依代表答案安排。
- 分頁後保留標頭或對象說明。紙本不得依賴點擊、展開或自動帶入；排序、計算及動態比較須保留指令、選項與填寫位置。

#### 檢驗方式與通過條件

首次製作逐題執行；既有頁面重驗受影響範圍。結果記在既有修訂稿註記，包含題組／欄位 ID、操作、結果及待修位置。同一版本、同一範圍的證據可在章節間共用。

| 檢驗 | 操作與通過條件 |
| --- | --- |
| 原稿與題型 | 逐項對照題目、選項、限制、對象及維度，再由 HTML 反查依據；不得遺漏、變意或無據新增 |
| 欄位與答案 | 每欄填入代表答案並走到最後一步；控制與空間合適，每個動作有位置，沒有重複或缺少前置資訊 |
| 選擇與上限 | 測互斥、並存、到達與超過上限、取消、重選及跨組範圍；「其他」可選取並填寫 |
| 排序與計算 | 測首末名、確認、重排、空白、無效、有效、修改與條件切換；結果、公式、單位及下游更新正確 |
| 比較矩陣 | 每個對象與維度逐格操作，改變前置結果後重查；資料不串格，未知或不適用有合理路徑 |
| 暫存與清除 | 重新整理後正確還原；清除後不殘留舊結果或勾選 |
| 桌面、手機與紙本 | 檢查空白及代表答案狀態；無遮蔽、裁切、失聯，紙本不操作網頁也能完成 |

不適用的題型須說明原因；未做、失敗與通過分開記錄。任何一題仍有遺漏、錯誤對應或無法完成，該篇不能標示通過。

#### 自動檢查的範圍

- `scripts/check/rules/worksheet-style-check.cjs` 檢查選擇題標示、控制配置、「其他」與示例；`scripts/check/static.cjs` 檢查 ID 與標籤。兩者不判斷題型是否選對或表格是否完整。
- 指定頁面的計算、排序與比較測試只證明該頁行為。新增或修改特殊互動時，須把正常與可重現錯誤案例接入正式測試，不能只檢查元件存在。
- AI 提示詞的可代入欄位固定使用網站支援的 `【欄位名稱】`，不得改用外觀相近但不會觸發代入的 `〔〕`、`（）` 或純文字標籤。內容稿先按提示詞出現順序列出每個括號的來源；網站設定的綁定組數、順序與括號數必須完全一致。自動檢查涵蓋所有頁面的括號、欄位設定與人工理由；實際互動須先在每個來源欄位填入可辨識且不同的代表答案，再測即時代入、修改、還原、清除、未作答及複製一致性，不能只檢查提示詞中存在括號。
- 來源完整性、代表答案、元件選擇、紙本空間及前後依賴仍由人工驗收。現有自動列印主要檢查空白頁面。
- 發現同類問題時先修共同原因並檢查本次範圍內其他題組；規則寫入、測試通過與逐篇人工通過分開回報。

### 人工驗收

#### 選擇題與範例的固定呈現

- 一般選擇題以 `question-heading` 包住 `h3` 與 `answer-mode`；「單選」「可複選」「最多選三個」置於題目右側灰字。題目及活動小標不加數字或字母流水號。
- 選項使用 `choices`／`choice`。只有短詞或短句的選項在桌面版採緊湊格狀排列，每列最多三個；不得為填滿橫向空間拉成整列長格，也不得排成四個以上而壓縮辨識與點選空間。一般選項的可見文字移除空白後，任一項超過 `config/quality-policy.json` 的 `choices.maxCompactCharacters` 時，整組使用 `choices-stacked`，讓每個選項獨占一列；選項內另行呈現的灰字示例不計入字數。即使每項未超過該門檻，同組有三個以上一般選項在桌面三欄版面實際換行時，也使用 `choices-stacked`。手機版一律為單欄。單選用同名 radio，複選用 checkbox；畫面文字不加 A／B 等人工標號。若其他指令引用代號，須同步改成能直接辨識的文字。欄位 ID、name 及內部代號不因移除顯示標號而變更。
- 選項文字只描述可勾選的判斷，不以連續底線模擬填答位置。需要讀者補充內容時，使用 `inline-input`；「其他」使用 `other-choice` 與 `other-input`。若題目只要求勾選該敘述，不另外收集文字，移除底線即可。
- 「短標題：說明」型選項由 `looksLikeHeading` 與 `choice-copy`／`choice-title` 呈現層級。句尾冒號或直接引語不拆行；不得改變原文語意、值或 ID。
- 「其他」的控制與輸入須同在 `choice other-choice`，標籤使用 `choice-toggle`。矩陣沿用 `matrix`／`matrix-options`。
- 任何用來引出示範的「如」「像是」「比如」「舉例」「範例」「例」「示範答案」「起手句」及其他同義說法，一律改成置於示範文字開頭的「例如：」。示範須另起一行並使用灰色小字，不得把「例如：」留在指令或一般正文中。一般示範用 `example-note`，選項內示範用 `choice-inline-example`；AI 提示詞內的示範亦同。
- 一般選項的示範放在同一個綠色 `choice` 格內。若示範屬於「其他」選項或其文字輸入，則放在該綠色選項格外；若示範屬於一般填答欄，則放在該欄橫線下方。這兩類格外示範使用 `example-note`，不得塞入 `other-choice`、`answer-field` 或輸入控制內。
- MD 的句內示範用 `<!-- example -->` 與 `<!-- end-example -->`，獨立示範可用 `<!-- example: 內容 -->`。標記不得包住必要指令或輸入位置。

實際驗收須走過受影響活動及前後依賴，並核對：

1. 讀者不靠額外解釋即可知道動作、資訊與作答位置。
2. 來源與成品雙向一致；本次修改未刪除必要資訊、提示、判準或問題。
3. 每個開放欄位都有對應的「例如：」灰字示範。
4. 修訂稿與 HTML 的題目、選項、範例、提示、欄位及順序一致；被新形式取代的舊要求已由修訂稿移除，原稿不變。
5. 沒有相關經驗、事情未發生、選「其他」或不同分支時仍可繼續；AI 要求分析的資訊都有輸入位置。
6. 桌面、手機與列印的題型位置、顯示標號、「其他」、冒號層級、示例灰字、字重及缺字均正確。

首次製作與相關修改的回報須列出結尾位置、首頁與主標一致性及未完成項目。影片對應本次查證時說明概念與練習關係；沿用時指出既有依據與未受影響範圍。部分抽查不得宣稱全篇通過。使用者指出漏項後，修正該項並檢查同規則其他位置；可重現的漏判加入負向測試。

## 缺字與原意

`scripts/check/browser.cjs` 依實際文字與字重比對精簡字型 manifest。一般字重有字不代表粗體有字；標點與讀者輸入由系統字型接手，不能自動換詞。

先重建精簡字型。若原始字型也缺字，以不改題意的近義詞替換，並同步檢查標題、摘要、頁首、頁尾及入口；搜尋詞可保留舊說法。不能改寫的標題、名稱或引述，才在 `fontFallbackExceptions` 記錄精確 `scope`、`font`、`character`、完整 `text` 與 `reason`，並人工確認備援字型。不得以整頁或整類字元略過。

## 字型流量

字型分為 `compact/home/` 與 `compact/EP編號/`；各學習單只下載自己的字元，原始字型只供重建且不發布。首頁列表使用系統字型，新增文章不得擴張首頁品牌字型。

使用 `font-display: block`；不得改為 `optional`。靜態檢查驗證雜湊、大小、新舊、引用與顯示設定；瀏覽器檢查請求數、流量及慢速載入的版面位移。超過政策預算時減少無用字元或拆檔，不能直接提高門檻。

## A4 列印

每篇在正常字型及下載失敗兩種狀態下確認：A4 尺寸正確、工具列隱藏、內容不溢出或進入頁尾保留區、PDF 與 HTML 頁數一致且頁碼連續。

過長時先在完整活動間分頁並保留作答空間，再調間距。不得以 `overflow: hidden` 藏問題；手機樣式須限於 `screen`。自動檢查以空白學習單為主；版型或分頁變更後仍須逐頁查看 `.qa/reports/` PDF，極長答案或拉大文字框時另看列印預覽。

## 內容索引與容量

`data/catalog.json` 只含卡片欄位；`data/search-index.json` 在第一次搜尋時載入並重用。文章全文及各頁 `metadata.json` 只在開啟個別頁面後讀取。

首頁一次只渲染一頁；搜尋比對完整索引。輸入法組字期間不搜尋，連續輸入套用延遲；分頁不重新下載。分類、排序或搜尋變更回第一頁，舊的非同步結果不得蓋過新操作。

容量測試依政策檔筆數驗證首末頁、跨頁搜尋、排序、分類、純文章、零結果、載入失敗重試及組字輸入；模擬資料不得寫入正式索引。效能檢查涵蓋目錄與索引大小、搜尋耗時及畫面項目數。

## 執行與報告

### 影片嵌入、連結與發布門檻

- 每篇預設必須有影片。影片核對分成「身分」與「教學對應」：集數、標題、網址正確只證明身分，不能證明內容能支援練習。
- 固定來源為[煩惱影片查找系統－資料庫](https://docs.google.com/spreadsheets/d/1H8BpNhd5LytJfUue3AnFXwe2fujVZWEPdFFlr8oXP34/edit?gid=0#gid=0)。以 A 欄集數定位，讀 D 欄標題與儲存格超連結，以 E 欄稿件名稱交叉核對；不得用集數推算列號。純文字沒有網址時讀 hyperlink、格式連結或公式。表格只讀，不修改。
- 指定表格無紀錄、空白或不符時，再查原作者來源。實際開啟並核對集數、標題、主題與頻道；格式正確不能代替核對。收到集數即可自行查找，不要求使用者重貼資料庫或逐篇提供網址。
- 只有首次配對且缺乏證據、學習單缺少影片必要資訊、概念或引述有疑義、重新配對，或使用者明確要求時才讀逐字稿。先提出疑點並查相關段落，足以判斷即停止；只缺網址時不讀全文，也不另搜文章。
- 查證結果在修訂稿以 `<!-- video-alignment: 逐字稿位置；影片概念；對應活動及連結理由 -->` 記錄。配對、概念與活動未變且既有證據具體時可沿用；排版或不改原意的文字修改不重查。
- 讀者應能由目標、說明或活動看出如何使用影片概念。若只缺連接語，可依來源補寫；若須另創論點，標示「教學對應待確認」，停止該篇發布並提出具體落差，其他工作照常繼續。
- 找不到或無法核對時標示「影片待核對」並阻止該篇發布；不得猜網址、改配相似影片或刪除按鈕。只有使用者明確確認無影片時，才可在 `videoExceptions` 記錄集數、原因與核准依據。
- `catalog/worksheets.json` 的 `videoUrl` 是影片網址的唯一來源；先在此維護已核對網址，再執行產生程序。工具列的「觀看影片」會由 metadata 自動載入；有結構化來源的頁面，其播放器由 HTML 產生器建立。
- 內容確認後進入「製作 HTML」時，先核對 `videoUrl` 與影片標題。有結構化來源的頁面由產生器將影片放在首張頁面的主標與 `hero-question` 之後、「學習目標」之前；`videoUrl` 轉成對應的 HTTPS embed URL，`title` 使用來源中的已核對影片標題，並保留延遲載入、播放權限與全螢幕設定。不得直接修改產生後的 HTML。
- 本機驗收須分開確認頁面內播放器與工具列連結：播放器在桌面與手機可見、載入目標正確且不破壞版面，iframe 標題可辨識；工具列按鈕可見且網址等於索引值。列印時不得因播放器產生空白頁、裁切或遮蔽學習內容。只有核准例外可省略影片相關介面。

發布前逐項核對原稿與修訂稿、學習目標、使用說明、結尾、AI 提示詞、小標題、影片、索引搜尋、作答、手機及列印。任一必備內容、來源或檢查缺漏或失敗，都不能標示完成或提交發布。回報須區分規則修改、內容完成、本機驗證、push、部署及線上抽查。

完整命令見 [維護命令](commands.md)。報告、截圖與 PDF 位於 `.qa/reports/`；GitHub Actions 保留檢查 artifact。檢查器會注入缺字及過高區塊驗證負向案例；不得刪除負向測試或把既有錯誤加入通過清單。

### 暫時移除與重新分配

暫時移除時，從 `catalog/worksheets.json` 與公開目錄下架，保留本機原稿、修訂稿、HTML 及原索引資料於 `content/原EP編號/`，並在修訂稿檔首加入 `publication_status: pending-reassignment`。重新產生與建置後，確認搜尋無結果且 `_site/` 沒有舊頁面。未授權發布時只能回報本機移除。

待重新分配內容不因舊檔名恢復上架。收到新配對後，重新完成影片身分與教學對應，再同步標題、集數、索引、頁尾與連結；完成後才移除待分配狀態。保留原稿來源與舊配對依據，欄位意義未變時保留 ID。
