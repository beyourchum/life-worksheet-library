# 品質檢查與修正方式

本文件說明驗收規則與失敗後的處理方式。數值門檻、分頁大小與容量測試筆數統一放在 [quality-policy.json](../quality-policy.json)；不要在程式或文件建立另一份可變設定。

## 缺字與原意

`scripts/browser-check.cjs` 逐頁讀取實際文字的字型和字重，對照精簡字型 manifest 的中文字元表。一般字重有字，不代表粗體也有字。標點及讀者自行輸入的字由系統字型接手，讀者作答不得自動換詞。

出現缺字時先確認是否只是精簡檔尚未重建。若原始字型也缺字，使用意思相近且不改變題目判斷的用語；同步檢查標題、摘要、頁首、頁尾與相關入口。搜尋詞可保留原詞，讓舊說法仍能查到內容。

若是不能改寫的專有名稱或引述，在 `fontFallbackExceptions` 記錄 `scope`、`font`、`character`、完整 `text` 與 `reason`，並人工確認系統備援字型。例外必須對應精確文字，不允許以整頁或整類字元略過檢查。沒有理由的例外無效。

## 字型流量

字型依 `compact/home/` 與 `compact/EP編號/` 分開。首頁內容列表使用系統字型；新增文章不會擴張首頁的品牌字型。各學習單只下載自己的字元，原始字型保留給重建工具使用，不發布到網站。

字型使用 `font-display: block`：首次開啟短暫等待字型，下載完成即套用；超過瀏覽器的等待期限則先顯示系統字型，稍後自動替換，不需要重整。不得改為 `optional`，以免慢速首次載入一直停留在備援字型。

靜態檢查驗證字型雜湊、大小、來源新舊、引用位置與 `font-display`；瀏覽器檢查實際請求數與流量，並模擬慢速字型載入，確認沒有版面跳動。超過預算時應減少不需要的字元或拆分檔案，不應直接提高門檻。

## A4 列印

每份學習單都在正常字型與字型下載失敗兩種情況下檢查：

- 頁面寬高符合 A4，工具列隱藏。
- 內容沒有超出頁面，也未進入頁尾保留區。
- PDF 實際頁數與 HTML 分頁數相同，頁碼連續且總頁數正確。

內容過長時，優先在完整活動區塊之間分頁，保留作答空間，再調整間距。即使 `overflow: hidden` 將問題藏起來，檢查仍會依內容實際高度及頁尾位置判定失敗。手機版樣式必須限定 `screen`，避免影響列印。

自動檢查主要驗證空白學習單；使用者輸入極長答案或自行拉大文字框後，仍需查看列印預覽。版型或分頁變更後，必須打開 `.qa/reports/` 的 PDF 逐頁確認，不只看測試通過。

## 內容索引與容量

`data/catalog.json` 只包含卡片必要欄位。`data/search-index.json` 包含搜尋詞及權重，第一次搜尋才下載，後續在記憶體重用。文章全文維持各自頁面；學習單只讀取自己的 `metadata.json`。

首頁一次只渲染一頁結果，但搜尋會比對完整索引。輸入法組字期間不觸發搜尋，連續輸入會延後短暫時間再執行；分頁只切換現有結果，不重新下載資料。分類、排序或搜尋變更回到第一頁，非同步舊結果不得蓋掉新操作。

容量測試使用政策檔指定筆數的模擬內容，驗證首末頁、跨頁搜尋、排序、主題篩選、純文章入口、零結果、載入失敗重試與組字輸入。測試資料不會寫入正式索引。效能檢查包括目錄／搜尋索引大小、搜尋耗時和畫面項目數。

## 執行與報告

完整執行步驟見 [README.md](../README.md#檢查與發布)。報告寫入 `.qa/reports/quality-report.json`，同資料夾包含首頁截圖與各集 PDF；GitHub Actions 保留檢查報告 artifact。

檢查器會自行注入缺字與過高的區塊，確認檢查能抓到錯誤。不要刪除這些負向測試，也不要把正常內容的既有錯誤加入預期通過清單。任何測試失敗都會阻止發布。
