# 產物與清理

`_site/` 是可重建的發布產物。其他產物依用途存放：

| 位置 | 用途 |
| --- | --- |
| `.qa/reports/` | 最近一次完整驗收的報告、PDF 與截圖 |
| `.qa/work/EP編號/` | 進行中的截圖、試填 PDF、一次性腳本與日誌；跨集使用集數範圍，無集數放 `work/general/` |
| `.qa/archive/` | 尚未確認可刪除的舊過程資料；不能當成有效來源或驗收結果 |
| `.qa/backups/` | 稿件版本與其他必要備份 |
| `.qa/deps/` | 本機檢查額外依賴 |

臨時產物不得散放在專案或 `.qa/` 根目錄，也不另建 `output/` 保存重複預覽。完成驗收後清理可重建的過程檔；可重複使用的檢查工具移入 `scripts/check/`，測試案例移入 `tests/`，並接上對應驗收入口。搬移或刪除前，先確認引用、占用狀態及可恢復來源；不要中止其他工作來強制整理。

`data/`、各集 `metadata.json` 與精簡字型由產生程式更新並隨來源提交。原始字型、授權檔與執行所需依賴必須保留。

## 稿件備份

- 每輪實質改稿前，將受影響的既有稿件備份到 `.qa/backups/EP編號/YYYYMMDD-HHmmss/`，保留原檔名；路徑重複時加序號，不覆蓋備份。實質改稿包括題意、選項、作答規則、段落或活動的增刪與重組；同一輪的小幅改字不重複備份，新建稿件不建立空備份。
- 原稿快照不得覆蓋；有效稿沿用原路徑，備份只供復原。復原時依 [內容來源與同步](workflow.md#內容來源與同步) 核對版本及 HTML 差異。
- 稿件與備份留在本機，不強制加入 Git 或發布。任務結束時，只清理已確認完全重複且另有可恢復來源的副本；保留含獨有修訂內容的版本。
