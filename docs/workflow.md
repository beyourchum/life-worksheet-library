# 維護工作流程

本文件是內容製作、網站轉換、本機驗收與發布順序的唯一來源。品質通過條件見 [quality](quality.md)，授權停止點與回報格式見 [AGENTS.md](../AGENTS.md)。

## 依任務進入流程

先確認分支、既有差異、有效來源與授權停止點，再依下表選擇最早受影響的關卡。已通過且未受影響的判斷沿用既有證據；不得因為重新接手而從頭重做。

| 任務 | 起點與執行範圍 | 本機交付證據 |
| --- | --- | --- |
| 新內容或修正題意 | 關卡 1、2；依授權進入後續關卡 | 原稿、修訂稿與代表答案試填 |
| 已定稿內容製作 HTML | 關卡 3 → 4 → 5 | 結構化來源、產生結果、互動與列印驗收 |
| 單頁版面或互動修正 | 關卡 3；重跑受影響的 4、5 | 單頁差異與相關活動回歸結果 |
| 共用程式、產生器或目錄重整 | 盤點依賴 → 局部回歸 → 完整本機驗收 | 引用與入口正確、既有測試及發布產物驗證 |
| 維護文件或規則整理 | 核對權威來源 → 修改 → 連結與一致性檢查 | 文件差異、有效連結；不產生網站 |
| 只檢查現有成果 | 關卡 5 的適用檢查 | 檢查結果與問題位置；不重建來源 |
| 已授權發布 | 確認最終版本驗收後進入關卡 6 | commit、push、部署、線上抽查各自的證據 |

一般維護不套用內容的四階段進度標記。改動工具或目錄時，以 [儲存庫結構](repository.md) 確認寫入與發布邊界，以 [維護命令](commands.md) 選擇入口。

## 四個交付階段與六個執行關卡

對使用者的交付順序固定為：

1. 抓取並保存底稿為 `_source.md`。
2. 完成內容修訂與驗收，保存為 `_corrected.md`。
3. 製作 HTML，包含網頁排版、題型、互動、影片、衍生資料及本機驗收。
4. 依授權發布，包含提交、推送、部署及線上抽查。

相對應的標準指令固定為 `EP編號 → 修正內容／製作 HTML → 發布網站`。每個停止點依 [AGENTS.md 的「下一步」決策表](../AGENTS.md#下一步決策表) 提供連續的下一條指令；只有完成發布與線上抽查後才結束提示。

六個關卡是上述四階段的內部執行拆分，用來隔開需要模型判斷的工作與可直接由既有程式完成的工作；不得因切換關卡而重讀全部材料或重做已通過的模型判斷。

每一關只接收前一關已確認的輸出。後續發現前一關有問題時，回到負責關卡修正，再重跑所有受影響關卡；不得在版面或發布階段順帶改變題意。

| 交付階段 | 執行關卡 | 模型使用 | 完成條件 |
| --- | --- | --- | --- |
| SOURCE | 1. 任務盤點與來源保存 | 預設不用；只有來源互相矛盾、缺漏或需語意辨識時才使用 | 有效底稿已核對並保存為不覆寫的 `_source.md`；範圍、阻礙及停止點已記錄 |
| CORRECTED | 2. 內容定稿 | 需要；由 `worksheet-content-tw` 設計或審查內容並以代表答案試填 | `_corrected.md` 穩定；內容問題有明確位置 |
| HTML | 3. 網站轉換 | 有新的或變更的題型、互動、排版或內容同步時需要；純沿用既有結構時只處理差異 | 文字、欄位、控制、提示詞、影片及前後依賴與有效稿一致 |
| HTML | 4. 衍生資料 | 不用；直接執行既有產生程序 | 公開資料、metadata 與精簡字型已更新 |
| HTML | 5. 本機驗收 | 執行既有自動檢查不用；只有人工語意／視覺驗收或失敗無法由報告直接定位時才使用 | 自動檢查通過；桌面、手機、互動、試填與列印有實際證據 |
| 發布 | 6. 發布驗證 | 預設不用；只有失敗需判斷修正方式時才使用 | `origin/main`、部署與線上成果都包含目標變更 |

只要求檢查時不修改內容；只要求內容或文件時不啟動網站轉換；製作授權不包含發布。使用者指定逐階段審閱時，在指定關卡停止，否則依既定停止點持續執行。

模型只處理需要語意、內容、題型、互動或視覺判斷的差異。環境檢查、依賴安裝、Git 狀態、檔案搬運、既有命令、產生、建置、可直接判讀的檢查報告、提交、推送及部署屬一般維護，不為這些步驟重啟內容或網站技能。前一階段已有可追溯的核對結果時直接沿用；只有來源、題意、結構或實際結果改變，才重做受影響的模型判斷。

## 關卡 1：任務盤點

內容工作沿用既有工作稿或 `_corrected.md` 的本機註記；一般維護將下列資訊留在對話，不另建單次文件：

- 目標、授權依據與停止點。
- 有效來源、目前進度、既有未提交修改及待確認事項。
- 可修改範圍，以及必須保留的題意、選項、限制、比較維度、前後依賴與欄位 ID。
- 適用的內容、互動、瀏覽器、列印及發布檢查；待執行與已完成分開記錄。
- 交接所需的修改位置、檢查證據、未解問題、已嘗試修正與連續失敗輪數。

開始或接手時先核對檔案與記錄。若有落差，先辨識有效來源，不用新分支或「最終版」副本繞過版本問題。

內容工作須在本關卡取得指定底稿並保存為 `content/EP編號/EP編號_source.md`。檔案只保存接收時的原稿快照，不進行內容潤飾且不得覆寫；檔案搬運、命名與完全一致的格式轉存不使用模型。只有候選來源不只一份、內容缺漏、來源互相矛盾，或必須靠語意判斷才能辨識有效底稿時，才啟用模型並只讀取判斷所需範圍。

## 關卡 2：內容定稿

### 起點與確認方式

| 起點 | 處理方式 |
| --- | --- |
| 尚無學習單題目 | 從題材、文章、簡報或企劃設計題目、作答流程與收束 |
| 已有完整或部分底稿 | 保留可用內容，依授權審查修正，只補缺少部分 |

使用者只輸入集數（如 `EP42`）時，預設授權完成該集內容，依本關卡完成內容設計或審查、代表答案試填與人工驗收，交付 `content/EP編號/EP編號_corrected.md` 供確認；此簡寫不授權網站轉換、提交或發布。若已明確授權完成學習單或網站，則持續完成內容、轉換與本機驗收，不增加定稿確認點。

工作稿保留有效版本、來源、授權、題號對應、每題目的、作答規則、必要情境、提示、範例、前後依賴、代表答案及未解問題。主持人使用的目的、時間與核對紀錄可留在本機註記，不必全部公開。

依 [內容結構與作答設計](quality.md#內容結構與作答設計) 主動完成主標、問題式小標、學習目標、使用說明、各題指令與作答位置、必要判準、逐欄示例、結尾及 AI 提示詞。單選／複選限制、排序、計算、比較維度、作答分支與特殊題型的狀態契約都須寫入內容稿。AI 提示詞的每個括號須標明前文來源；沒有來源才標示人工補充及理由。

完整成稿後才能以代表答案逐題試填。試填時先把同題中的時間、地點、人物、行動、感受、原因、意義與下一步逐一列出，確認每個向度都有自己的作答位置；再依代表答案長度決定單行或多行欄。結尾或 AI 提示詞若仍是占位文字，關卡 2 不得完成，也不能交給網站端代寫。內容品質及驗收方式見 [共通內容品質](quality.md#共通內容品質)、[內容結構與作答設計](quality.md#內容結構與作答設計)與[人工驗收](quality.md#人工驗收)。

## 關卡 3：網站轉換

先依[內容來源與同步](#內容來源與同步)辨識材料、原稿快照和有效工作稿。內容技能負責題目、說明、範例、收束及 AI 提示詞；網站技能負責元件、版面、互動與操作介面。

接入本站時核對 EP 編號、影片及必備內容；影片規則見[影片嵌入、連結與發布門檻](quality.md#影片嵌入連結與發布門檻)。只阻擋依賴問題的步驟，其餘已授權工作繼續。

在 `catalog/worksheets.json` 維護 `ep`、`title`、`summary`、`category`、`searchTerms`、內容連結及已核對的 `videoUrl`。分類取自 `catalog/categories.json`，搜尋詞種類取自 `config/search.json`。每個作答欄位使用唯一且穩定的 ID；意義未變時不得更換。

新頁面或完整改造的頁面使用 `worksheet-sources/EP編號.json` 保存網頁結構；來源納入版本控制但不發布，再由 `pnpm run html:worksheet -- EP編號` 產生 `worksheets/EP編號/index.html`。產生器只統一工具列、頁首、影片、頁碼、頁尾與共用資源，不從自由格式 Markdown 推測題型；`pages[].bodyHtml` 必須依有效稿明確寫出欄位與元件。特殊題型優先使用共用元件，特殊版面以 `config/worksheet-layouts.json` 登錄的 `layoutVariants` 宣告。不得在頁面放 `<style>`、`style` 屬性或自行加入單集 CSS／JS。既有未遷移頁面維持原責任與檢查方式，實際修改時逐篇遷移，不整批重製。

有結構化來源的頁面由 `html:worksheet` 產生播放器：影片網址取自 `catalog/worksheets.json`，標題取自 `worksheet-sources/EP編號.json` 的 `videoTitle`，位置在首張頁面的主標與 `hero-question` 之後、「學習目標」之前。既有未遷移頁面在實際修改時先遷移，再由來源重新產生 HTML。工具列的「觀看影片」連結仍由 metadata 載入，不能代替頁面內播放器。影片身分與教學對應須先核對，再產生 HTML 並驗收。

一般填答、暫存、清除與列印之外的互動，優先沿用 `assets/worksheet-components.js` 和 `assets/worksheet-components.css`，以 `data-*` 宣告限選、排序、條件顯示或計算；不得新增以集數命名的 CSS／JS。只有單一題目專屬的公式或流程可留在具名計算器中；同類功能再次出現時應沿用共用契約。

特殊版面不等於頁面可自行帶樣式。需要不同欄寬、手機標題換行或其他可重用差異時，先在 `config/worksheet-layouts.json` 登錄具名變體，再由 `data-layout-variant` 套用 `assets/worksheet.css` 中的範圍選擇器。學習單 HTML 不得包含 `<style>` 或 `style` 屬性；只有會影響單一題目語意且無法共用的結構留在頁面標記中，第二次出現同類需求時移入共用元件。

新增或修改特殊題型時，將內容稿定義的適用狀態加入瀏覽器測試，包括初始、上限、空白、無效、修改、重做、暫存還原、清除及列印。AI 提示詞測試須涵蓋即時代入、修改、還原、清除、未作答括號及複製一致性。

進入下一關前，逐項確認主標在脫離來源脈絡後仍直觀、已核對影片已嵌入指定位置、短選項每列不超過三個、不同作答向度已拆欄，以及結尾與 AI 區已由有效稿同步。AI 區須實際填寫各來源欄位，確認位置、內容、括號順序、即時代入及複製結果正確。若有效稿本身缺漏，退回關卡 2；若有效稿正確而網頁誤植、漏嵌影片或互動有誤，留在關卡 3 修正。

## 關卡 4：衍生資料

依 [單集製作](commands.md#單集製作) 或 [全站交付](commands.md#全站交付) 執行產生程序，更新 HTML、公開資料與精簡字型。寫入範圍見 [個別入口](commands.md#個別入口)。衍生檔案不手動編輯；產生失敗時先修正來源或產生器，再重跑受影響步驟。

## 關卡 5：本機驗收

單集製作依 [單集命令](commands.md#單集製作) 檢查現有稿件、結構化來源、HTML、影片、桌面、手機與空白列印；不因其他既有單元缺稿而阻擋該集。完成後依受影響範圍，以代表答案檢查互動與前後依賴。單集結果不得標示為完整本機驗收通過。

若修改共用程式、字型來源、產生器、索引／搜尋程式、品質政策或檢查規則，先完成目標頁與相關代表頁的局部回歸；整批交付或發布前依 [全站交付命令](commands.md#全站交付) 完成產生、建置與完整驗收。工具或測試目錄重整時，也須確認載入路徑、CI 入口與發布內容未改變。

`verify` 檢查現有檔案，不重建衍生資料或 `_site/`。需要定位問題時依 [個別入口](commands.md#個別入口) 分開執行。來源頁面的診斷不代表發布產物通過。

自動檢查後，仍須依 [A4 列印](quality.md#a4-列印) 逐頁查看 PDF，並依 [人工驗收](quality.md#人工驗收) 實際試填。純工具路徑或文件重整不改動頁面內容與呈現時，人工語意、試填與視覺驗收可沿用未受影響的有效證據；須明列沿用範圍，不能宣稱重新人工驗收。

人工檢視指出問題後，修正本身不等於驗收完成；須重跑受影響的產生、靜態、建置、瀏覽器、試填或列印檢查，最終回報不得把「已修改」寫成「已通過」。

## 關卡 6：發布驗證

發布前確認本次成果已整合至既有 `main`，且提交不含無關變更。記錄目標 commit SHA，推送 `origin/main`，追蹤該提交的 GitHub Actions 與 Pages，最後抽查正式網站的具體變更。

push 成功、部署成功及線上抽查通過是三個獨立狀態。原授權內可修正的失敗直接修正、重驗並繼續；只有需要新決策、權限或擴大範圍時才停止。

## 多篇任務

先集中盤點範圍、來源、既有修改與影片資料，再一次完成一篇。每篇依序通過內容定稿、網站轉換、試填及桌面／手機／列印驗收後才進入下一篇；第一篇的轉換方式尚未驗證時不得擴用整批。

同類問題先修共同原因。局部修正後重跑受影響關卡，整批交付前再以最終版本完成整合驗證。單篇遇到需使用者判斷的來源矛盾時，記錄阻礙並繼續其他不受影響的已授權工作。

## 內容來源與同步

`_source.md` 保存接收時的原稿快照，不覆蓋；`_corrected.md` 保存依授權完成且已驗收的有效內容與修改依據；`worksheet-sources/EP編號.json` 保存可重建的網頁結構；HTML 負責版型與互動。本站不把自由格式 MD 直接轉成 HTML：已建立結構化來源的頁面由該來源產生，其他既有頁面仍先改修訂稿再同步 HTML。兩種路徑都須完成 MD／HTML 雙向核對，不能把產生器當成內容判斷工具。

找不到 MD 時，依序檢查集數目錄、`.qa/backups/` 與 Git 歷史。確實沒有來源時，才由實際交付檔案或原始文件建立並核對；不得用 HTML 反推原稿。摘要、分類與搜尋詞只在 `catalog/worksheets.json` 維護。

暫時移除與重新分配依[品質規則](quality.md#暫時移除與重新分配)；備份及驗收產物依 [產物與清理](artifacts.md)。

## 失敗與重驗

讀取完整日誌，記錄檔案或題號、重現方式、預期與實際結果，修正原因後重跑受影響關卡。失敗後尚未執行的檢查仍標示「尚未檢查」。

同一錯誤連續兩輪修正並重驗仍失敗時，停止重複嘗試，整理已試方案及所需決策或權限。不得修改測試、放寬門檻、隱藏內容或新增例外來取得通過。
